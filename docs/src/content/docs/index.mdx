Upkeep keeps my repositories and the projects that use them up to date, and
shows what needs doing in one place. It's built for my own use, in the open.

It's being built. The plan and the decisions still open are tracked in
[timmo001/upkeep#1](https://github.com/timmo001/upkeep/issues/1), and these docs
grow as each part lands. The server, workers and the `releases`, `labels` and
`bump` jobs are in; see [Running it](/running).

## What's decided

- A worker runs jobs, and a web dashboard shows their state beside pull
  requests, issues, notifications and releases.
- Jobs start on a new release of one of my repositories, on a schedule, or from
  a run button.
- Changes are checked before they're pushed, and a failure is fixed forward
  rather than left waiting.
- Every first-party repository rolls its releases out to its consumers through
  Upkeep.
- The server runs as a Home Assistant app. It keeps job state and logs, hands
  out jobs and serves the dashboard in the Home Assistant sidebar.
- Workers run on whichever of my desktop machines is on, and take jobs from the
  server, so each job runs once.
- It's one `upkeep` binary: the server, the worker, the CLI, MCP and Code Mode
  are all parts of it.
- Consumers are found from what's already in each repository, such as workflow
  pins and `package.json` dependencies, so no list is kept.
